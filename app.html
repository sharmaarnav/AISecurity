Application & API Layer

The application and API layer is where AI capabilities are exposed to users and integrated into business workflows. AI agents, plugins, and APIs dramatically expand the attack surface: they can read files, browse the web, execute code, and send emails. Excessive permissions, insecure API keys, unvetted plugins, and blind trust in AI-generated code are the defining risks at this layer.

Agent PermissionsAPI SecurityPlugin SecurityAI-Generated Code
Excessive AI Agent PermissionsCritical

AI agents granted broad permissions (file system access, email sending, database writes, shell execution) operate as highly capable insiders. When an agent is compromised via prompt injection or malicious tool output, every permission it holds becomes an attack vector. This is OWASP LLM Top 10 #08: Excessive Agency.

Technical DetailAn LLM agent with read/write filesystem access, outbound HTTP, and email sending can exfiltrate data, pivot laterally, and establish persistence if a prompt injection succeeds. The blast radius of a compromised agent equals the sum of its granted permissions. "Human-in-the-loop" requirements are often bypassed when agents are trusted to act autonomously on behalf of users.
Insecure API Key ManagementHigh

Hardcoded or improperly stored API keys for AI services (OpenAI, Anthropic, Google Gemini) grant unrestricted model access and incur unbounded costs. Leaked keys are immediately scraped from public repositories by automated bots within seconds of exposure.

Technical DetailGitHub's secret scanning detects and notifies vendors of leaked keys, but damage often occurs within minutes of a commit. AWS, OpenAI, and Anthropic keys found in public repos result in immediate abuse: cryptomining, large-scale inference, or data exfiltration. Environment variables in Docker images, CI/CD logs, and client-side JavaScript bundles are common leak vectors for AI API keys.
AI Plugin & Tool Chain VulnerabilitiesHigh

AI plugin ecosystems (ChatGPT Plugins, LangChain tools, LlamaIndex connectors) execute arbitrary code on behalf of the LLM. Malicious or vulnerable plugins can exfiltrate conversation history, execute system commands, or silently redirect the AI's actions. Third-party tool chains introduce the same supply chain risks as npm or PyPI packages.

Technical DetailOAuth flows in AI plugins are frequently implemented incorrectly, allowing CSRF attacks that connect victim accounts to attacker-controlled plugins. Plugin manifest files specify data access scopes that LLMs may over-grant. MCP (Model Context Protocol) servers with broad filesystem or shell access become high-value targets once adopted in agentic pipelines.
Blindly Trusting AI-Generated CodeHigh

Developers shipping AI-generated code without security review introduce SQL injection, command injection, hardcoded credentials, and insecure cryptography at scale. AI code assistants optimise for functionality, not security. Studies show AI-generated code contains security vulnerabilities at a higher rate than carefully reviewed human-written code.

Technical DetailGitHub Copilot and GPT-4 code completions reproduce vulnerable patterns from training data. Research (Pearce et al. 2022) found 40% of Copilot-generated security-critical code contained vulnerabilities. AI models suggest deprecated crypto (MD5, SHA1), construct SQL queries by string concatenation, and generate SSRF-vulnerable HTTP clients. Code review tools like Semgrep and CodeQL are essential post-generation gates.
🔒
Principle of Least Privilege for AI Agents
  • 1Audit every tool and permission granted to AI agents; remove anything not strictly required for the task
  • 2Implement human-in-the-loop confirmation for high-impact actions: sending emails, modifying databases, deleting files
  • 3Scope tool permissions to read-only where possible; use separate credentials per agent with scoped access tokens
  • 4Log every agent tool call with inputs and outputs; alert on anomalous action sequences

Secure AI API Key Management
  • 1Store all AI API keys in a secrets manager (AWS Secrets Manager, HashiCorp Vault, Azure Key Vault) — never in code or environment files
  • 2Enable GitHub secret scanning and push protection to block commits containing API keys
  • 3Rotate AI API keys on a schedule and immediately after any suspected exposure; set spending limits on all AI accounts
  • 4Use short-lived tokens and server-side proxies instead of embedding keys in client-side applications

AI Code Security Review
  • 1Gate all AI-generated code through static analysis (Semgrep, CodeQL, Bandit) before review and merge
  • 2Require security-aware code review for all AI-assisted PRs; train developers on common AI code vulnerability patterns
  • 3Use AI security assistants (GitHub Advanced Security, Snyk Code) to catch vulnerabilities introduced by Copilot suggestions
  • 4Maintain a "known-bad AI patterns" checklist: SQL string concatenation, MD5/SHA1 usage, shell=True in subprocess calls

2023BreachCritical
ChatGPT Plugin OAuth CSRF Vulnerability

Security researchers discovered that numerous early ChatGPT plugins implemented OAuth flows without CSRF state parameters. An attacker could craft a link that, when clicked by a victim, silently connected the victim's ChatGPT account to an attacker-controlled plugin, giving the attacker full read access to the victim's conversations and any plugin-enabled data sources.

ImpactFull conversation history exfiltration and potential data access to connected third-party services. OpenAI worked with plugin developers to remediate. Demonstrated that AI plugin OAuth security must be held to the same standard as standard OAuth implementations.
Key LessonAI plugin OAuth flows must implement state parameters, PKCE, and redirect URI validation. Security review of plugin manifests and OAuth scopes must occur before approval in any AI plugin marketplace.
2023BreachHigh
Samsung Source Code Leak via ChatGPT

Samsung engineers pasted proprietary source code, internal meeting notes, and hardware schematics into ChatGPT to assist with debugging and summarisation tasks. The data was submitted to OpenAI's API and potentially used in model training. Samsung subsequently banned ChatGPT use on company devices and infrastructure.

ImpactConfidential intellectual property submitted to a third-party AI provider. Samsung imposed a company-wide ban on external AI tools. Prompted industry-wide review of data governance policies for AI tool usage.
Key LessonOrganisations must establish clear AI usage policies specifying what data categories may be submitted to external AI APIs. Self-hosted or enterprise-tier AI deployments (with data processing agreements) are required for sensitive workloads.
2024ResearchHigh
Indirect Prompt Injection via Email in AI Assistants

Researchers demonstrated that AI email assistants (using LLMs to read and draft emails) could be hijacked by sending specially crafted emails containing hidden instructions. When the AI assistant processed the email, it executed the attacker's instructions — forwarding emails, exfiltrating calendar data, or sending phishing replies — without user awareness.

ImpactFull AI agent hijack via email content. Demonstrated that any AI with mailbox access and action capabilities is vulnerable to indirect injection from untrusted email senders. Real-world agentic AI email products were affected.
Key LessonAI email agents must treat all email content as untrusted user input. Sensitive actions triggered by AI agents (send, forward, delete) require explicit human confirmation and must not be triggerable by email content alone.
