Network & Infrastructure Layer

AI systems communicate constantly — fetching training data, serving inference requests, aggregating gradients, and calling external APIs. Network attacks intercept model inputs and outputs, steal API credentials, disrupt AI services, or pivot into isolated training infrastructure.

TLS/mTLSAPI SecurityDDoSZero Trust
MITM Attacks on AI API TrafficCritical

Intercepting unencrypted or improperly verified AI API calls steals model inputs, model outputs, and API authentication credentials. Any AI-powered application calling external APIs over untrusted networks is at risk.

Technical DetailSSL stripping on legacy AI integrations, certificate pinning bypass in mobile AI apps, rogue CA certificates on corporate networks intercepting AI API traffic. Even HTTPS is compromised if TLS cert validation is skipped — common in ML SDK quick-start examples that use verify=False.
AI API Credential TheftHigh

OpenAI, Anthropic, AWS Bedrock, and other AI API keys exposed via source code commits, application logs, environment variable leakage, or network interception. Stolen keys enable unauthorised usage, significant financial charges, and access to proprietary fine-tuned models.

Technical DetailGitHub secret scanning finds thousands of new exposed AI API keys monthly. Container image layers frequently contain credentials from build environments. API keys in client-side JavaScript are trivially extractable via browser devtools. Automated bots claim exposed keys within minutes of GitHub commits.
DDoS on AI Inference ServicesHigh

AI inference is computationally expensive — "model bombing" (sending maximum-length inputs) exhausts GPU resources with far fewer requests than traditional DDoS. AI APIs are uniquely vulnerable to resource exhaustion attacks.

Technical DetailA single request with 128,000 tokens to a large LLM consumes significant GPU compute. Coordinated attacks sending max-length requests can exhaust all available GPU capacity at a fraction of the cost of volumetric DDoS. AI services with no per-request compute limits are trivially DoS-able.
Lateral Movement to AI Training InfrastructureHigh

Compromised edge systems, VPN endpoints, or developer workstations pivot into isolated AI training networks. SSH key theft, stolen VPN credentials, and SSRF vulnerabilities in internal AI services are common vectors.

Technical DetailAI training infrastructure is typically on "trusted" internal networks with minimal east-west controls. SSRF in Jupyter notebooks can reach EC2 metadata (169.254.169.254), internal APIs, and training data stores — converting a notebook compromise into cloud credential theft.
🔒
Enforce Encryption Everywhere
  • 1Require TLS 1.3 for all AI API communications; disable TLS 1.0/1.1 on all AI service endpoints
  • 2Implement mTLS for service-to-service AI communications using Istio or Linkerd service mesh
  • 3Never use verify=False or suppress InsecureRequestWarning in any AI SDK code — fix the cert, not the check
  • 4Apply certificate pinning in mobile AI applications; use HSTS on all AI web frontends

AI API Key Security
  • 1Store all AI API keys in secrets management: HashiCorp Vault, AWS Secrets Manager, or Azure Key Vault
  • 2Make all AI API calls server-side only — never expose keys in client-side JS, mobile app binaries, or public repos
  • 3Enable GitHub Advanced Security secret scanning and GitGuardian on all repositories containing AI code
  • 4Set billing alerts on AI API accounts; rotate keys on schedule and immediately on any suspected exposure

🛡️
DDoS Protection & Rate Limiting
  • 1Implement rate limiting at API gateway: per-API-key token limits per minute/hour/day
  • 2Add hard request size limits for AI API inputs (max tokens per request)
  • 3Use CDN/DDoS protection (Cloudflare, AWS Shield Advanced) for public AI API endpoints
  • 4Implement graceful degradation: return cached or simplified responses under load

2023BreachCritical
Mass OpenAI API Key Theft Campaign

Security researchers discovered 50,000+ valid OpenAI API keys exposed in public GitHub repositories. Automated bots claimed keys within minutes of exposure. Victims reported thousands of dollars in unexpected charges; some had proprietary system prompts and conversation histories exfiltrated.

ImpactFinancial damage to individuals and companies. Exposed proprietary business logic. OpenAI implemented proactive key revocation for detected exposures.
Key LessonUse server-side API calls only. Enable GitHub secret scanning. Set billing alerts. Time from GitHub push to key theft is measured in minutes.
2024BreachHigh
Hugging Face Platform Token Exposure

Hugging Face disclosed unauthorised access to their Spaces platform, with shared secrets including user API tokens potentially compromised. Hugging Face revoked all affected tokens. Researchers' private model weights and training scripts may have been accessed.

ImpactErosion of trust in a platform used by millions of AI researchers. Potential theft of proprietary model weights and training code.
Key LessonMonitor your Hugging Face access logs; rotate tokens after any platform security incident. AI tool providers are high-value concentration-of-IP targets.
