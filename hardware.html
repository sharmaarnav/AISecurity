Hardware Layer

The physical foundation of every AI system — GPUs, TPUs, CPUs, memory, and AI accelerators. Physical security is the bedrock all other layers depend on. A compromised hardware layer makes every software-level protection meaningless.

Supply Chain Side-Channel TPM GPU Security
Supply Chain Hardware TrojansCritical

Malicious hardware implants inserted during chip manufacturing or assembly. Near-impossible to detect post-manufacturing. A compromised GPU or AI accelerator can silently exfiltrate model weights, introduce computation errors, or act as a kill-switch activated remotely.

Technical DetailHidden circuitry at silicon level can trigger under specific instruction sequences. Nation-state actors and sophisticated groups target AI chip supply chains. Grey-market GPU procurement poses the greatest risk for ML training farms.
Side-Channel AttacksHigh

Extracting secrets by measuring power consumption, electromagnetic radiation, or timing differences during AI computation. Can recover model weights and private training data without any software vulnerability.

Technical DetailDifferential Power Analysis (DPA) reconstructs neural network parameters from GPU power traces. Cache timing attacks reveal model architecture. EM probing of AI accelerators during inference leaks intermediate activation values. Hertzbleed-style frequency attacks affect DVFS-enabled processors.
Cold Boot & Physical TamperingHigh

Direct physical access enables DRAM content extraction after power loss (cold boot), JTAG debug port exploitation for direct memory read/write, and voltage/clock glitching to bypass security checks on AI edge devices.

Technical DetailLPDDR4/5 RAM retains data for seconds to minutes after power removal; cooling with liquid nitrogen extends this to hours. Rowhammer attacks via crafted memory access patterns can flip bits in stored model parameters.
Insecure Debug InterfacesMedium

JTAG, SWD, and UART debug interfaces left enabled on production AI hardware allow direct memory access without software authentication. Brief physical access is enough to extract complete model weights and system secrets.

Technical DetailMany AI edge devices (Jetson Nano, Coral TPU, custom ASIC boards) ship with debug interfaces enabled for developer convenience. JTAG provides full control — memory read/write, breakpoints, register access — with no authentication at the hardware level.
🏭
Trusted Supply Chain Management
  • 1Maintain a Hardware Bill of Materials (HBOM) for all AI computing components; source only from authorised distributors
  • 2Require vendor hardware security attestation and certifications (CC EAL, FIPS 140-3) for AI accelerators
  • 3Implement incoming hardware inspection with X-ray and electrical testing for critical deployments
  • 4Follow NIST SP 800-161 Cybersecurity Supply Chain Risk Management practices

Memory Encryption & Side-Channel Hardening
  • 1Enable AMD Secure Memory Encryption (SME) or Intel Total Memory Encryption (TME) on all AI servers
  • 2Use AMD SEV or Intel TDX for AI workloads in virtualised/cloud environments
  • 3Apply EMI shielding to GPU/TPU enclosures in sensitive deployments; install power line filters
  • 4Prefer constant-time implementations for any cryptographic operations protecting AI model keys

Debug Interface Hardening
  • 1Permanently disable JTAG/SWD via fuse blowing or hardware write-protect before production deployment
  • 2Conduct regular hardware security audits to verify debug interfaces are disabled on all AI inference hardware
  • 3Use tamper-detecting enclosures that erase keys if the device is physically opened

2018BreachCritical
Bloomberg Supermicro Server Implant Allegations

Bloomberg reported that Chinese intelligence agencies planted microchips smaller than a pencil tip on Supermicro server motherboards used by Apple and Amazon AWS. While disputed, it triggered massive supply chain security reviews industry-wide and prompted Congressional hearings on hardware supply chain risk.

ImpactSupermicro stock fell 50%. Both Apple and Amazon denied the report. US intelligence investigated. Regardless of truth, exposed how hardware supply chain attacks are plausible at scale.
Key LessonHardware supply chain verification is existentially important. Even unproven allegations reveal how systemic hardware risk is to AI infrastructure.
2021ResearchHigh
GPU Side-Channel Neural Network Extraction

University of North Carolina researchers demonstrated extracting complete DNN model parameters — weights and architecture — from GPU memory side channels alone. No software vulnerability required. Achieved >99% reconstruction accuracy using only physical proximity and power measurement equipment.

ImpactAI model IP can be stolen from GPU hardware observable signals without any code access. Forced rethink of "air-gapped" AI model security guarantees.
Key LessonSoftware access controls alone cannot protect model IP. Hardware-level memory encryption for AI accelerators is necessary.
2022ResearchHigh
Hertzbleed CPU Frequency Side-Channel

Intel and AMD CPUs found vulnerable to Hertzbleed — a frequency side-channel exploiting Dynamic Voltage and Frequency Scaling (DVFS). Attackers can remotely measure CPU frequency variations to extract cryptographic keys protecting AI model weights, requiring no physical access.

ImpactAll modern Intel and AMD processors affected. Microcode updates released. Power management features in AI accelerators introduce previously unknown side channels.
Key LessonAI accelerator power optimisations introduce side channels. Constant-power-draw mitigations and cryptographic library updates are required.
2023ResearchMedium
Cold Boot Attacks on AI Edge Devices

Researchers recovered AI model weights from NVIDIA Jetson Nano and Raspberry Pi with Coral TPU devices by freezing LPDDR4 memory modules and reading contents minutes after power removal — demonstrating that edge AI deployments have no protection against physical memory extraction.

ImpactFull model weight recovery from deployed edge inference devices. Edge AI security cannot rely on data deletion at shutdown.
Key LessonEdge AI deployments require hardware-level memory encryption. LPDDR5 with inline encryption is minimum for high-value deployments.
