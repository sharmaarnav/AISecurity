Virtualization & Containers Layer

Modern AI workloads run almost exclusively in Docker containers orchestrated by Kubernetes, or in VMs on cloud hypervisors. Container escapes, Kubernetes cluster takeovers, and hypervisor vulnerabilities expose entire multi-tenant AI infrastructure, allowing attackers to move from one customer's training job to another.

DockerKubernetesContainer EscapeVM Escape
Container Escape to HostCritical

Vulnerabilities in container runtimes (runc, containerd, CRI-O) allow an attacker inside one AI container to escape to the host OS, gaining access to all other AI containers, GPU resources, and Kubernetes node credentials.

Technical DetailCVE-2019-5736 runc overwrite: container escape via /proc/self/exe overwrite, affecting all Docker and Kubernetes deployments. CVE-2022-0847 Dirty Pipe: write to read-only files enables container escape. Privileged containers and hostPath mounts trivially enable escape without any CVE.
Kubernetes Cluster TakeoverCritical

Misconfigured Kubernetes clusters with unauthenticated API servers, overly permissive RBAC, or default service account tokens allow complete cluster takeover. AI inference services on Kubernetes are high-value targets for cryptomining and model IP theft.

Technical DetailCommon misconfigs: API server bound to 0.0.0.0 with anonymous access enabled; cluster-admin ClusterRoleBinding for default service accounts; etcd exposed without TLS on :2379; pods with automountServiceAccountToken: true and broad RBAC permissions.
Insecure AI Container ImagesHigh

AI/ML Docker images on Docker Hub and Hugging Face Spaces frequently contain outdated OS packages, embedded API keys, model weights with hardcoded credentials, or outright malicious code in image layers.

Technical DetailTrivy scans of popular AI/ML Docker Hub images consistently find critical CVEs. Base images (python:3.10) go months without updates. Hugging Face Spaces images have been found with hardcoded API tokens. Pickle-based model files in images execute arbitrary code when loaded.
VM Escape via Hypervisor VulnerabilityHigh

Vulnerabilities in VMware ESXi, QEMU/KVM, or Hyper-V allow a guest VM to break isolation and access the host or other tenant VMs. On shared AI cloud infrastructure, this enables cross-tenant attacks on training data and model weights.

Technical DetailVMware ESXiArgs ransomware exploited CVE-2021-21974. QEMU escape via virtio-net, virtio-blk, and e1000 emulation demonstrated at Pwn2Own. vTPM implementations have had vulnerabilities allowing guest-to-host escalation targeting AI VM key material.
🐳
Secure Container Configuration
  • 1Set non-root USER in all AI Dockerfiles; use read-only root filesystems for inference containers
  • 2Drop ALL Linux capabilities and add back only what CUDA requires; never use --privileged flag in production
  • 3Apply seccomp default profile; AppArmor/SELinux for all AI workload containers
  • 4Sign container images with cosign (Sigstore); enforce signature verification at deployment via admission controller

Kubernetes Security Hardening
  • 1Enable Pod Security Admission with Restricted or Baseline policy for all AI workload namespaces
  • 2Implement RBAC with least privilege: scoped service accounts per AI workload; no cluster-admin for applications
  • 3Disable automountServiceAccountToken for pods that don't need API server access
  • 4Apply NetworkPolicies to isolate AI training pods from inference pods and external traffic
  • 5Run kube-bench to continuously check CIS Kubernetes Benchmark compliance

2018BreachCritical
Tesla Kubernetes Cluster Cryptojacking

Tesla's Kubernetes cluster was found fully exposed to the internet with no authentication. Attackers installed cryptocurrency mining software on Tesla's GPU-powered AI training infrastructure and attempted to access Autopilot training data. The admin console was publicly accessible on an undocumented port.

ImpactGPU-powered AI infrastructure hijacked for cryptomining. Potential access to Tesla Autopilot training data and model weights. Became the canonical example of Kubernetes misconfiguration risk.
Key LessonKubernetes API server must never be publicly accessible without authentication. Immediately audit cloud Security Groups for exposed Kubernetes ports (:6443, :10255, :2379).
2023BreachHigh
VMware ESXiArgs Ransomware on AI VM Infrastructure

Large-scale ransomware campaign exploiting unpatched VMware ESXi vulnerabilities encrypted thousands of VMs at research institutions, cloud providers, and AI companies across Europe and North America. AI training VMs with weeks of checkpoint data were encrypted and held to ransom.

ImpactWeeks of AI training progress lost at multiple universities and AI companies. Recovery required complete VM rebuild. Patches had been available 2+ years before exploitation.
Key LessonHypervisor patching must have the same urgency as OS patching. Immutable, offline backups of AI training checkpoints are essential — not optional.
